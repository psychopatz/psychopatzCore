# Harness Acceptance — Portable Social State

## Core portability

Must pass with PsychopatzCore only:

- create actors;
- sparse directed relationship;
- authorized event;
- bounded memory;
- retention/consolidation;
- serialize/reload;
- revision conflict;
- synthetic adopter extension;
- no ProjectHoomans/DT symbols loaded.

## Hoomans adopter

Must prove:

- rich Hoomans social events can update Core generic state once;
- Hoomans-specific conduct/faction/knowledge remain owner-specific;
- Unified Semantic Evidence retrieves bounded Core/adopter context;
- Social Conversation Director consumes projections without persistence ownership;
- duplicate generic relationship writers are absent after migration.

## DynamicTrading / DTAbstract adopter

Must prove with Project Hoomans disabled:

- trader has stable Core actorID;
- DTAbstract abstract/remote trader retains Core social state;
- authoritative trade event updates relationship/memory once;
- relationship pricing context consumes Core state;
- social history can affect dialogue/negotiation inputs without owning market price/stock;
- remote contact does not require physical NPC;
- materialization later reuses same actor/social revision.

## Cross-mod

Combined Core + Hoomans + DTCommon + DTAbstract/DTHoomans:

- one actor identity;
- one generic directed relationship state;
- no duplicate trade/social event application;
- provider transitions retain social memory;
- player reconnect does not fork identity;
- bounded replication only.

## CodeBuilder

- canonical portable social policy compiles through existing framework;
- Core and adopter packages route by owner;
- unknown refs/effects fail closed;
- unbounded retention/fan-out fails validation;
- two generations are byte-identical;
- generated output is not hand-authored;
- source maps identify canonical source.

## Retention/consolidation

Test SCENE/SHORT/LONG/ANCHOR semantics, saturation, repeated events, high salience, lazy expiry, provenance and deterministic replacement/merge.

## Future non-LLM autonomy seam

Synthetic consumer can query one candidate actor/action and receive bounded relationship/memory/provenance/threat features.

It cannot mutate social state or execute an action.

Same external opportunity plus different history/personality can yield different features.

## Scale

Measure:

- actors with zero relationships;
- sparse contacts;
- repeated same-pair events;
- many abstract traders;
- high-observer event;
- long-duration retention;
- reload/reconnect.

Acceptance requires storage proportional to meaningful social contacts/history bounds, not population squared.

## Final regression

Relevant Core, Hoomans and DynamicTrading tests pass; Semantic Harness/CodeBuilder determinism/static/Kahlua checks pass where applicable; source saves remain untouched; no native launch or Workshop publication is required for developer acceptance.
